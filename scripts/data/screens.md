# Карта экранов приложения OrroFi

Составлено 16.11.2026 около 21:00 (Europe/Madrid). Только подготовка: код не писался, ничего не публиковалось.

Эталон экранов — утверждённый кликабельный прототип v5: https://muratpod.github.io/orrofi-proto/ (ветка `design/v5-proto-full`). В приложении те же идентификаторы. Бренд актуальный: OrroFi, палитра брендбука (тёмная #13254A и #FFA566, светлая #F6F4EE и #B5500F, шрифт Nunito в брендбуке).

## Как читать эту карту

- **Раздел A** — вход, главная, услуги, заказ, счета, Mi gestor, профиль и приватность. В iOS это единственный раздел, который входит в сборку Release.
- **Раздел B (Mi red)** и **раздел C** (семья, удаление данных сети, сброс, «я этого не делал») в iOS сейчас только в Debug. В прототипе они уже все есть.
- В прототипе **139 идентификаторов**: служебные `all` (карта прототипа) и `wip` («в разработке») плюс **137 пользовательских экранов** (53 в A без карты, 37 в B, 47 в C). В iOS `ScreenID` для A — 53 позиции, включая `all` и `wip`, но без двух экранов заказа мобильной (`order-movil`, `order-movil-ok`), которые есть в прототипе.
- Данные на всех снимках — фиктивные (демо). Секреты и реальные персональные данные не используются.
- «Годен для сайта» — чистый кадр текущего бренда, без панелей прототипа («Oscuro / Claro / ES / Mapa») и без старого бренда GhoFi / лайм.
- Обзорные листы «72 кадра Mi red» (PR #58, ветка `design/v5-mynet-delete`) и файлы с пометкой OUTDATED на сайт не ставим: первые — справочные сетки, вторые — устаревший бренд.

| Телефон добавлен | `fam-13d` | Успех, уведомление другим | Семья | Нет |
| Код не совпал | `fam-13e` | Приглашение отменено | Семья | Нет |
| Сверка 6 цифр | `fam-14a` | Проверка, что это тот же дом | Семья | Нет |
| Приглашение отменено | `fam-14b` | Цифры не совпали | Семья | Нет |
| Извещение: телефон добавлен | `fam-15` | Пуш владельцу | Семья | Нет |
| Убрать этот телефон? | `fam-15b` | Подтверждение удаления | Семья | Нет |
| Телефон убран | `fam-15c` | Доступ закрыт, ключ сменён | Семья | Нет |

### Удаление данных Mi red

Цепочка от входа (`del-entry`) до результата: только владелец; при необходимости сначала почта; подтверждение Face ID; письма сразу и за 24 часа; отмена, если есть право (телефон владельца был связан не меньше 72 часов до запроса). Экраны: `del-entry`, `del-owner`, `del-16a0`, `del-16a`, `del-16b`, `del-16b2`, `del-16c`, `del-sh-bio`, `del-16d`, `del-16d2`, `del-16e`, `del-16e2`, `del-16f`, `del-16g`, `del-16h`. Снимков нет ни на один из них.

Это **удаление данных домашней сети**, не удаление аккаунта из раздела «Приватность» (A). На сайте их нужно объяснить отдельно.

### Сброс Mi red и «я этого не делал»

Сброс сети: `rst-entry`, `rst-owner`, `rst-sms`, `rst-17m`, `rst-17a`–`rst-17l`, `rst-sh-bio`, `rst-sh-bio-c`. Сюда входят причина, подтверждение, лимит «не больше трёх раз за 30 дней», отмена и пуш-извещения. Снимков нет.

Сигнал о чужих действиях: `rp-18a` («Вы видели то, чего не делали?») и `rp-18b` (заявку приняли). Снимков нет. Это отдельная функция безопасности, её стоит показать на страницах «Безопасность» и «Инструкции».

## Экраны и функции без годного снимка

Это задачи для Design: снять с настоящего iOS (предпочтительно) или дорисовать в утверждённом бренде. Прототипные кадры с панелью «Oscuro / Mapa» можно использовать только после обрезки. Устаревшие GhoFi/лайм не использовать. Веб-демо чата с лаймовыми кнопками не использовать.

Приоритет — то, что пойдёт на сайт-визитку (по одному сильному кадру на функцию). Внутри функции ниже перечислены экраны, которых не хватает.

### Высокий приоритет (без них нельзя описать заявленные возможности)

1. **Заставка и вход по коду.** Нет живого `launch`, `sh-faceid-open`, `login-code`, `loginerr`, `loginexp`, `sh-nocode`. Есть только форма телефона и экран блокировки. Заставку частично закрывает `brandbook-usage-splash-430x932.png`.
2. **Новый клиент и покрытие.** Полностью нет: `onb`, `onbnone`, `onb2`, `onb3`.
3. **Услуги кроме фибры.** Нет экранов радио, мобильной связи, докупки гигабайт, PIN/PUK и услуги Wi‑Fi (`radio`, `mobile`, `sh-gb`, `sh-pinpuk`, `wifi`).
4. **Заказ: дата визита и мобильная линия.** Нет `order-date`, `order-movil`, `order-movil-ok`. Сводка и «заказ отправлен» уже есть.
5. **Карточка счёта.** Нет `invoice`. Список счетов есть только в прототипе с панелью.
6. **Mi gestor целиком, кроме главного чата.** Нет передачи человеку (`handoff`, `handoffoff`), тикетов, лимита, диктовки.
7. **Mi red — подключение и защита роутера.** Нет всей цепочки `net-entry` … `net-0h` и системного разрешения локальной сети. На сайте иначе не объяснить, как сеть привязывается к телефону.
8. **Mi red — ежедневное управление.** Нет устройства, паузы интернета, нового устройства, канала и соседей, безопасности, истории, перезапуска, домашнего и гостевого Wi‑Fi, «вне дома». Есть только общий вид и «состояние сети» в прототипе (с панелью) плюс рекламный кадр брендбука.
9. **Семья.** Нет QR, сверки кода, добавления и удаления телефона. Есть только список в прототипе (с панелью).
10. **Приватность и данные.** Нет выгрузки данных, подтверждённого удаления аккаунта, запланированного удаления. Полный экран «Privacidad» есть только как тестовый снимок iPhone SE. Зато есть сильный кадр «удаление запрещено при действующих договорах».

### Средний приоритет (нужны для инструкций и честности)

11. **Настройки.** Нет экранов уведомлений, включения Face ID и выхода (`notifset`, `sh-faceid`, `sh-logout`). Профиль уже снят хорошо.
12. **Установка целиком.** Есть смена времени визита; нет полного экрана хода установки (`install`).
13. **Разрешение на пуш-уведомления** (`push-why`).
14. **Состояния пусто / ошибка / офлайн** (`stempty`, `sterror`, `stoffline`).
15. **Удаление данных Mi red, сброс сети, «я этого не делал».** Все 30+ экранов цепочек `del-*`, `rst-*`, `rp-18a/b` без снимков. Для сайта достаточно 6–8 ключевых кадров: запрос, подтверждение Face ID, письмо/пуш, отмена, результат, форма сигнала.

### Низкий приоритет (можно не снимать все вариации)

16. Дубли светлой/тёмной темы и EN там, где испанский тёмный кадр уже есть (кроме главной и входа — они уже сняты).
17. Все вариации пушей «с правом отмены / без права» и лимита заявок на сброс.
18. Системные листы Face ID и «Локальная сеть» — лучше короткая схема «так выглядит запрос iOS», без имитации системного окна один в один, если Design не рисует его отдельно.

### Что переснимать, хотя кадр формально есть

- Все 11 снимков прототипа — обрезать панель или снять те же экраны в iOS.
- `ios-snapshot-privacidad-iphone-se.png` — заменить кадром обычного iPhone.
- Не использовать устаревшие кадры и веб-демо вне утверждённого бренда.

## Замечания для Design и Mobile

- Предпочтительный источник — настоящее iOS-приложение, демо-данные, тёмная тема ES как основная (так выглядит бренд на главной), плюс 1–2 кадра светлой темы.
- Разделы B и C в Release сейчас выключены: чтобы снять Mi red и семью с приложения, нужна Debug-сборка или отдельное «да» на съёмку.
- В текстах прототипа и приложения ещё стоят юридические заглушки (`[EMAIL PRIVACIDAD]`, `[URL POLÍTICA]`, `[OPERADOR SOCIO]`, `[RESPONSABLE]`, `[TELÉFONO GRATUITO]`). На сайт и в новые макеты их выносить нельзя.
- Иконка приложения в брендбуке есть; в коде main ещё может встречаться старая. Для сайта брать иконку из orrofi-preview, как уже решено смотреть с Муратом.
